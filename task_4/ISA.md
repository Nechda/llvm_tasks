# Скалярная система команд (ISA)

Формат текстового ассемблера: одна инструкция на строку, операнды разделяются
запятыми, регистр результата указывается первым. Комментарии начинаются с `;`,
метки записываются как `name:`. Регистры изменяемые, их тип определяется именем:
`r_*` — i64, `f_*` — IEEE float32, `c_*` — i1. Перед чтением регистру должно быть
присвоено значение. Целочисленная арифметика выполняется по модулю 2^64;
сравнения и преобразования между целыми и вещественными числами — знаковые.
Деление `udiv` — беззнаковое. Деление на ноль и преобразование вещественного
числа за пределами диапазона целевого целого типа недопустимы.
Вещественные сравнения упорядоченные: при NaN результат ложный. Неявное слияние
арифметических операций и изменение порядка их группировки не допускаются.
Константы задаются десятичными или шестнадцатеричными целыми числами,
десятичными вещественными числами либо именами из `.const NAME, literal`.

`.buffer NAME, f32, COUNT` резервирует COUNT элементов float32 с изначально
неопределёнными значениями. `.const NAME, literal` объявляет константу времени
компиляции. Это директивы, а не исполняемые инструкции.
Исполнение начинается с первой инструкции.

## Обычные операции

Эти инструкции имеют обычную семантику переноса, арифметики, побитовых операций,
сравнений, преобразований и условного выбора:

| Инструкции | Операнды |
| --- | --- |
| `mov.i64`, `mov.f32` | результат, значение |
| `add.i64`, `sub.i64`, `mul.i64`, `udiv.i64`, `and.i64`, `xor.i64`, `or.i64` | результат, a, b |
| `add.f32`, `sub.f32`, `mul.f32`, `div.f32` | результат, a, b |
| `cmp.eq.i64`, `cmp.lt.i64`, `cmp.lt.f32`, `cmp.gt.f32` | регистр c_*, a, b |
| `sel.i64`, `sel.f32` | результат, условие, значение при истине, значение при лжи |
| `itof.f32`, `ftoi.i64` | результат, значение |
| `jmp` | метка |
| `br` | условие, метка при истине, метка при лжи |
| `halt` | нет |

`ftoi.i64` отбрасывает дробную часть с округлением к нулю. У `br` две явно
заданные цели перехода. `halt` завершает исполнение приложения.
Вызовов подпрограмм и стека вызовов в ASM нет.

## Индексные операции с памятью

`ld.f32 f_dst, [buffer + index]` и `st.f32 [buffer + index], value`
читают или записывают один элемент float32. Индекс — регистр i64 или целая
константа. Он измеряется **в элементах, а не в байтах** и должен находиться
в диапазоне [0, COUNT). Запись `[buffer]` означает индекс ноль. Вычисление
адреса и обращение к памяти составляют одну инструкцию ISA.

`fill.f32 buffer, start, count, value` записывает `value` в элементы полуинтервала
[start, start + count). Весь диапазон должен находиться внутри буфера.

## Инструкции на основе повторяющихся последовательностей

### `loop r_counter, step, limit, label`

Прибавляет `step` к счётчику и переходит на `label`, если обновлённый счётчик
**меньше `limit` при знаковом сравнении**; иначе выполняется следующая инструкция.
Операнды читаются до записи счётчика. Это завершающая инструкция цикла
с постусловием; счётчик необходимо инициализировать до входа в тело цикла.
Она объединяет частую последовательность `add / icmp / br`: 3,10% окон длины 3
при O2 и 4,72% при Os.

### `shade r_dst, height, minimum, scale`

Вычисляет `float32(height - minimum)`, умножает результат на `scale` с ещё одним
округлением до float32, преобразует произведение в знаковое i64 с отбрасыванием
дробной части и ограничивает результат диапазоном [0, 255]. Произведение должно
быть конечным и представимым как i64. Инструкция объединяет последовательность
отрисовки `fsub / fmul / fptosi / smax / umin`; её начало с предшествующей
загрузкой (`load / fsub / fmul / fptosi`) занимает около 2,50–2,75% окон длины 4.

### `madd.f32 f_dst, a, b, c`

Вычисляет `float32(float32(a * b) + c)` с **двумя отдельными округлениями**.
Это не слитная операция FMA. Семантика соответствует исполнению `llvm.fmuladd`
в задании 3 и сохраняет совпадение контрольных сумм кадров во всех режимах.

## Графические инструкции

`pixel x, y, argb` передаёт один пиксель слинкованной заглушке `simPutPixel`;
для каждого из трёх операндов i64 используются младшие 32 бита.
`flush` завершает кадр через `simFlush`. Обе операции — отдельные инструкции
ISA, а не универсальные вызовы функций. Запускающая программа инициализирует
и закрывает заглушку до и после исполнения приложения.

## Обоснование и исходные данные

Исходный код: `../task_1/app_Os.ir`, также воспроизведённый в задании 3.
Статистика: `../task_2/stats/patterns_{O2,Os}.txt`.
Индексные загрузки объединяют `getelementptr/load` (10,02–10,61% окон длины 2).
Скалярная арифметика заменяет векторы, созданные компилятором; сборка
и перестановка элементов векторов в ISA не входят. Для указаний LLVM о времени
жизни памяти, узлов SSA `phi` и преобразований индексов к узким целым типам
отдельные инструкции ASM не нужны. Таблицы соответствия инструкций из трасс
немного отличаются от сохранённого IR. Трассы охватывают только первые
100 миллионов пар операндов, а не полное исполнение 20 000 кадров.
